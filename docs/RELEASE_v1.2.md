# v1.2 —— P0 提示词强化 + 评测工程加固

> 标签：`v1.2-p0-eval-hardening`　｜　提交：`53fc03e`　｜　日期：2026-11-13

本轮做两件事：**让 Agent 答得更对**（提示词），**让评测更可信**（脚本加固 + 判据修正）。

---

## 一、改了什么

### 1. Agent 侧：P0 提示词强化（`prompts/main_prompt.txt`）

新增四条硬约束：

1. **强制检索**：凡涉及产品使用、故障、耗材、保养、选购、环境适配，必须先调 `rag_summarize`，不得凭常识直接回答；
2. **禁止编造**：只能依据工具返回内容作答；检索为空时明确回复"未找到相关资料"，不得用常识替代；
3. **回答完整**：必须覆盖参考资料中的关键步骤与数值，不得为简洁而省略；
4. **先追问再建议**：缺关键信息（面积/地面材质/机型/故障现象/预算）时，先追问 1–2 个问题。

同时修复了「报告生成强约束」段落的乱码（原文被截断成两句残缺文本），改为明确的 5 步流程：
`get_user_id → get_current_month → fill_context_for_report → fetch_external_data → 生成报告`。

### 2. 评测侧：脚本 v2 三道保险（`eval/run_eval.py`）

| 加固 | 解决的问题 |
|---|---|
| **额度预检** | 开跑前发 1 个 token 探测，403/欠费立即中止（此前曾因免费额度耗尽跑废一整轮 26 条） |
| **失败重试退避** | 403/429/超时自动重试 3 次（5s/15s/30s），并记录 `retries` |
| **基线元数据** | baseline 写入 `model / dataset_sha256 / git_commit / errors`；模型不同**拒绝横比**；有系统级错误**拒绝写基线** |

### 3. 判据修正（避免"假失败"）

- 归一化统一各类破折号：`－ – — −` → `-`（qwen-plus 输出 `2–3厘米`、`60–65分贝` 曾被判失败）；
- `must_contain` 支持同义词或：`["补电","充电","补充电量"]`、`[宠物|猫]`、`[悬崖传感器|防跌落传感器|防跌落]`。

### 4. 模型

默认对话模型切换为 **qwen-plus**（qwen-max 免费额度已耗尽）；基线按模型分开记录，互不覆盖。

## 三、已知问题（下一轮处理）

1. **F001「帮我写个股票代码」→ 回"未找到相关资料"**：弱拒答，未明确说明"超出服务范围"（拒答类 66.7% 的唯一失败）；
2. **R007 输出截断**：qwen-plus 思考文本过长耗尽输出预算，答案停在"最终回答："；
3. **R012「地面有水能清扫吗」**：检索未命中时模型自由发挥"少量水可用"，与知识库"不能进水"冲突（待 P1 提升检索质量）；
4. **qwen-max 免费额度耗尽**：需要充值或继续使用 qwen-plus。
