# 评测报告 v1（基线）

> 生成时间：2026-11-12　｜　被测版本：`react_agent.py`（create_agent + 7 工具 + 3 中间件）
> 数据集：`eval/dataset.jsonl`（25 条）　｜　跑批脚本：`eval/run_eval.py`
> 基线文件：`eval/baseline.json`　｜　原始明细：`eval/results/run_20261111_2218.jsonl`

---

## 1. 评测目标

回答三个问题：

1. 这个 Agent 在**真实业务问题**上，通过率是多少？
2. 失败时，错在**检索、工具、回答还是系统**？
3. 后续每一次改动（提示词 / 检索参数 / 记忆 / 上下文），**有没有变好、有没有变差**？

## 2. 数据集设计

25 条用例，5 类场景，每条带"期望工具 + 关键事实"：

| 类别 | 条数 | 考察点 | 示例 |
|---|---|---|---|
| retrieval | 15 | 是否会**先检索**再回答、关键事实是否覆盖 | "滤网可以水洗吗？" |
| tool | 4 | 工具选择、参数、调用链顺序 | "帮我生成上个月的使用报告" |
| refuse | 3 | 超范围/违规请求是否礼貌拒绝 | "帮我写个股票代码" |
| ambiguous | 2 | 信息不足时是否先追问 | "它坏了怎么办？" |
| multi_turn | 1 | 是否继承上文信息 | 上轮说"120平+养猫"，本轮问"那选哪个" |

字段含义：

```json
{"id":"R001","category":"retrieval","question":"...","expect_tools":["rag_summarize"],
 "must_contain":["充满电","建图"],"expect_refusal":false,"expect_followup":false,"thread":"t_R001"}
```

## 3. 评测方法（三层判据）

| 判据 | 做法 | 说明 |
|---|---|---|
| 工具 | `expect_tools ⊆ 实际调用`；报告类额外校验**取数主链顺序** | `fill_context_for_report` 是信号灯，只要求出现、不参与顺序 |
| 事实 | `must_contain` 归一化后全部命中；支持"同义词或"（如 `["补电","充电"]`） | 归一化：去空白、全半角、去标点差异 |
| 行为 | 拒答词表 / 追问标记 | 判据迭代见 §6 |

补充指标：

- **hit@3**：检索返回的 top-3 块**并集**是否覆盖全部关键事实；
- **分层归因**：失败自动标记为「工具层 / 检索·回答层 / 拒答层 / 追问层 / 系统层」；
- **耗时**：单例端到端耗时，统计均值与 P95。

## 5. 失败分析

| 用例 | 现象 | 根因 | 建议 |
|---|---|---|---|
| R008 / R010 / R015 | 未调用 `rag_summarize`，直接凭常识回答（答案碰巧正确） | `main_prompt` 写的是"信息不足才调工具"，模型自认为会就不查 | 改为强制："凡涉及产品使用/故障/耗材/选购，**必须先检索**" |
| R012 | "地面有水能清扫吗" 调用了 `get_user_location + get_weather`，且回答里出现工具未返回的"广州市" | 工具边界模糊 + 自由发挥 | 工具描述限定范围；提示词加"不得编造工具未返回的信息" |
| T001 | 把"上个月"算成 **2023-12**；`fetch_external_data` 被重复调用 4 次 | `get_current_month()` 返回**随机**月份，模型无法得知真实时间 | 改为 `datetime.now()`；提示词禁止重复调同一工具 |
| R005 | 知识库写"充到 50%"，模型答"充满电" | LLM 概括失真（RAG 幻觉） | 加强"必须基于参考资料"约束；后续用 rerank 提升命中质量 |
| A002 | "它坏了怎么办" 未追问，直接罗列全部故障 | 追问策略弱 | 提示词要求"信息不足先问清故障现象" |

## 6. 判据迭代说明（评测器本身也需要验证）

第一次跑（`run_20261111_2213.jsonl`）暴露出两个**判据 bug**，修正后重跑：

| 问题 | 修正 |
|---|---|
| 模型已礼貌拒绝（"您的请求与扫地机器人无关…"），却被判为"未拒答" | 拒答词表补充"无关 / 不相关 / 不符合 / 超出 / 无法提供"等表达 → 拒答类 0% → **100%** |
| 报告类要求 `fill_context_for_report` 必须最后调用，模型放在第 3 位就判失败 | 顺序校验只针对**取数主链**（`get_user_id → get_current_month → fetch_external_data`），信号灯工具只校验出现 |
| 关键词过严（知识库"补电"，模型说"充电"） | `must_contain` 支持同义词或写法 |

> 结论：**判据比模型更影响结论**。评测系统的第一条纪律是——先证明判据靠谱，再相信分数。

## 7. 已知局限

1. 样本量 25 条，仅覆盖高频问题，**置信区间宽**；
2. 规则评分对"语义正确但换了说法"不友好，需要 LLM-as-Judge 补充（并用人工标注校准）；
3. 知识库存在**内容冲突**（滤网周期：`维护保养.txt` 写"2 周"、`100问.txt` 写"1-3 个月"），评测会放大它；
4. `data/扫地机器人100问.pdf` 为扫描件（0 个可提取字符），当前未入库，需要 OCR；
5. 单轮为主，多轮仅 1 条。
