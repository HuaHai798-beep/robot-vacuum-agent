## Issue 1

**标题**：`[P0] 提示词强化：强制先检索 / 禁止编造 / 信息不足先追问`

**标签**：`enhancement`、`P0`

**正文**：

当前 v1.1 基线 73.1%（26 条），其中 7 条失败集中在三类：

1. **跳过检索**（R010 烟头、R015 瓷砖）：模型自认为"通用问题不用查"，`tools: []` 直接作答；
2. **编造/补充未返回信息**（R012 地面有水）：检索未命中后自行补充"部分机型防水"；
3. **缺信息不追问**（A001 型号、A002 故障）：直接给建议或罗列全部故障。

**改动**：在 `prompts/main_prompt.txt` 增加三条硬约束
- 凡涉及产品使用/故障/耗材/选购/保养，必须先调用 `rag_summarize`；
- 不得编造工具未返回的信息，检索为空时说明"未找到相关资料"；
- 缺少关键信息（面积/地面材质/故障现象）时，先追问 1–2 个问题。

**验收**：检索类 ≥ 85%、追问类 ≥ 80%，并保持拒答类 100%。

## Issue 2

**标题**：`[P1] RAG 优化：k / chunk_size 调参 + rerank`

**标签**：`enhancement`、`P1`

**正文**：

当前 `hit@3 = 87.5%`（16 条中 2 条未命中，如 R012「地面有水」）。知识库 88 块、`chunk_size=200`、`k=3`。

**改动**：
- `k` 3 → 5，`chunk_size` 200 → 400（重叠保持 10%）；
- 引入 rerank（如 DashScope `gte-rerank`），对 top-10 重排取 3；
- 每次只改一个变量，用同一份 26 条评测集对比。

**验收**：hit@3 ≥ 95%，检索类通过率提升，且 P95 延迟增幅 < 30%。

## Issue 3

**标题**：`[P2] 上下文管理：工具结果截断 + 历史摘要 + token 预算`

**标签**：`enhancement`、`P2`

**正文**：

单次问答中，每调用一次工具消息数 +2（1→3→5→7），RAG 返回的 3 段资料全文进入提示词，导致 token 与延迟偏高（P95 20.31s）。

**改动**：在 `agent/tools/middleware.py` 增加上下文管理中间件
- 工具结果超过 N 字截断并标注"已截断"；
- 历史超过 M 轮时生成摘要替换；
- 统计并记录每次调用的 prompt token 数。

**验收**：P95 延迟下降 ≥ 20%，token 消耗下降 ≥ 25%，通过率不下降。
